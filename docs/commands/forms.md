# Forms

Forms collect submissions from your site. These commands manage form definitions, read the
submissions they have received, and call the public Publishing API endpoints for a published form.

## Commands

```bash
marvin platform forms list
marvin platform forms get <id>
marvin platform forms create (--data <json|@file|-> | --file <path>)
marvin platform forms update <id> (--data <json|@file|-> | --file <path>)
marvin platform forms delete <id> --yes
marvin platform forms submissions <formId> [--limit <n>] [--offset <n>]
marvin platform forms get-published <slug>
marvin platform forms submit <slug> (--data <json|@file|-> | --file <path>)
```

!!! note "Required role"
    Any member lists and reads forms. Creating, updating and deleting a form needs **ADMIN** (or
    OWNER); reading a form's submissions needs **EDITOR**. See
    [Workspace roles](../reference/authentication.md#workspace-roles).

`--data` takes inline JSON, `@path` to read a file, or `-` to read stdin; `--file <path>` is the same
as `--data @path`. With neither, the command reads piped stdin.

## The form object

| Field | Description | Default |
|-------|-------------|---------|
| `name` | Form name (required on create) | |
| `slug` | URL identifier; generated by the server when omitted | |
| `description` | Free text | none |
| `status` | Form status | `draft` |
| `formSchema` | Object describing the form's fields | `{}` |
| `settingsJson` | Form settings object | none |
| `metadataJson` | Free-form metadata object | none |

`update` takes any subset of these fields.

## List and get

```bash
marvin platform forms list
marvin platform forms get 4d0c8e2a-91b3-4f6a-b7c5-3e1a2f9d6b80 --json
```

`list` columns: ID, Slug, Name, Status, Submissions (count), Created. `<id>` is the form's UUID.

## Create, update, delete

```bash
marvin platform forms create --data '{
  "name": "Contact",
  "slug": "contact",
  "description": "Website contact form",
  "formSchema": {"fields": []}
}'

marvin platform forms update 4d0c8e2a-91b3-4f6a-b7c5-3e1a2f9d6b80 --data '{"description": "Contact us"}'
marvin platform forms delete 4d0c8e2a-91b3-4f6a-b7c5-3e1a2f9d6b80 --yes
```

`create` and `update` print `Created form: <id> (<slug>)` / `Updated form: ...` on stderr and the form
on stdout. `delete` requires `--yes` (without it the command exits 1); with `--json` it prints
`{"deleted": "<id>"}`.

## Submissions

```bash
marvin platform forms submissions 4d0c8e2a-91b3-4f6a-b7c5-3e1a2f9d6b80
marvin platform forms submissions 4d0c8e2a-91b3-4f6a-b7c5-3e1a2f9d6b80 --limit 20 --offset 20 --json
```

Lists a form's submissions, newest first.

| Option | Description | Default |
|--------|-------------|---------|
| `--limit <number>` | Maximum number of submissions to return (a positive integer) | `100` |
| `--offset <number>` | Number of submissions to skip (0 or more) | `0` |

Columns: ID, Status, Submitted At, IP. `--json` also has `dataJson` (what the visitor sent),
`metadataJson`, `userAgent`, `referrer` and `processedAt`:

```bash
marvin platform forms submissions 4d0c8e2a-91b3-4f6a-b7c5-3e1a2f9d6b80 --json | jq '.[].dataJson'
```

## Published forms (Publishing API)

```bash
marvin platform forms get-published contact
marvin platform forms submit contact --data '{"name": "Ada", "email": "ada@example.com", "message": "Hello"}'
```

Both resolve the current workspace's slug and call the public endpoint for the form with the given
`<slug>` (the form's slug, not its id).

- `get-published` prints the published form definition.
- `submit` sends the JSON body as a submission, prints `Submitted to form: <slug>` on stderr and the stored submission on stdout.
